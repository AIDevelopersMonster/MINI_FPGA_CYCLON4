Priority Encoder 8-to-3 (pencode83)
🔧 Описание проекта

Этот модуль реализует приоритетный кодировщик 8-к-3 (8-to-3 Priority Encoder) на FPGA Cyclone IV.
Он принимает на вход восемь линий x[7:0] и выдаёт:

3-битный код активного входа y[2:0]

флаг Valid, который показывает, что хотя бы один вход равен 1

Кодировщик называется приоритетным, потому что при наличии нескольких активных входов он выбирает вход с наивысшим приоритетом.

В данном проекте приоритет распределён так:

x[7] — самый высокий приоритет
x[0] — самый низкий

Этот модуль соединяет переключатели SW с логикой кодировщика и выводит результат на LED.

🧠 Логика приоритетного кодировщика
⭐ Основная идея:

Приоритетный кодировщик — это устройство, которое ищет первый активный вход среди нескольких, согласно установленному порядку приоритетов.

Если на входе несколько «1», то:

обычный кодировщик может выдавать неопределённость

приоритетный кодировщик жёстко определяет, кто важнее

🔍 Как работает реализация в Verilog
Фрагмент ключевой логики:
for (i = 0; i <= 7; i = i + 1)
    if (x[i] == 1'b1)
    begin
        y     <= i;
        Valid <= 1;
    end


Цикл проходит по всем битам x[0] → x[7]

Каждый найденный «1» переписывает значение y

Последний найденный бит имеет максимальный приоритет

То есть, если одновременно:

x[2] = 1
x[6] = 1


Цикл дойдёт до i = 6 последним, значит:

y = 6
Valid = 1


Таким образом:

✔ x[7] — самый высокий приоритет

✔ x[0] — самый низкий приоритет

🧪 Пример работы
Вход (x[7:0])	Активные биты	Результат y	Valid	Причина
00000000	нет	000	0	нет «1»
00001000	x[3]	011	1	единственный "1"
01001100	x[2], x[3], x[6]	110	1	побеждает x[6]
10000001	x[0], x[7]	111	1	побеждает x[7]
🧭 Почему кодировщик считается приоритетным?

Обычный кодировщик предполагает, что только один вход активен.
Если активных входов больше — результат становится неопределённым.

Приоритетный кодировщик решает эту проблему:

Вводится иерархия входов (кто важнее)

Определяется единственный победитель

Вывод всегда чёткий и однозначный

Практически это важно, когда:

входы идут от разных датчиков

несколько событий могут происходить одновременно

нужно решить, что должно быть обработано первым

📘 Теория: зачем нужен приоритет?
Обычные применения:
✔ Системы прерываний процессора

Устройство с более высоким приоритетом должно обработаться первым.

✔ Аппаратные State Machines

Если поступают несколько сигналов, FSM выбирает главный.

✔ Комплексные логические узлы

Когда несколько условий пытаются выбрать одно действие.

✔ Мультиплексоры / арбитры

Порт №7 важнее порта №3 → отдаём доступ №7.

✔ Клавиатурные контроллеры

Нажато несколько клавиш → выбираем ключевую.

📌 Почему цикл for делает его приоритетным?

Потому что порядок обхода:

0 → 1 → ... → 7


и последний найденный «1» переписывает результат.

Поэтому в этой реализации:

✔ x[7] имеет максимальный приоритет
✔ x[0] имеет минимальный приоритет

Именно это и делает кодировщик приоритетным.

🔧 Синтезируемость

Код полностью синтезируем на FPGA.

Компилятор создаст цепочку условий, примерно такую:

if (x[7]) y=7;
else if (x[6]) y=6;
else if (x[5]) y=5;
...


Даже несмотря на использование for.

▶ Как проверить на плате MINI_FPGA (Cyclone IV)

Подайте CLK = 50 МГц

Двигайте переключатели SW7…SW0

На LED2..LED0 появится код

Светодиод Valid включится, если есть хотя бы один «1»
